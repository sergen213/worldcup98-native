# Tournament & team-history data — WC98 (pass 7, 2026-11-03)

Evidence: `analysis/pass7/teamhist.txt` + `analysis/pass7/options.txt` (PyGhidra runs
GhidraWc98Tri.py / GhidraWc98Opt.py), disk files under `FE/TEAMHIST.<lang>/`.

## Confirmed — team-history file pair (.HIS + .TRI)
- Loader `FUN_00489f58` (callers 0x457892, 0x458278, 0x467cac): builds path
  `"fe\teamhist.eng\du.his" + lang*0x19`, where **lang = byte at options block `DAT_0060cbc8+0x1c`
  (`>>0x18`)** — the MACH Language field from the options.sav map (OPTIONS_SAV_WC98.md). The `.eng`
  component is likewise language-selected by the caller set; on disk: `FE/TEAMHIST.{ENG,DA,DU,FR,GE,...}`.
- Record stream API (thin wrappers over EA win_fileio, assert strings `win_fileio.c`):
  open `FUN_004cf5e0`, read-record `FUN_004cfaa0` (position + fetch), advance `FUN_004cfb00`,
  close `FUN_004cfa70`. Same API serves `.TRI` string reads (`FUN_0049f5a0` = arena alloc from the
  per-stream block, critical section at stream+0x3c).
- **.HIS geometry check (exact predicate in code):** file size `> 3` and
  `nIdx*2 + nIdx*nRows*4 + 8 <= fileSize`, where `nIdx = u16 @stream+0x20`, `nRows = u16 @stream+0x1e`.
  ⇒ layout: 8-byte header, index table of `nIdx` × u16 (string offsets into the paired `.TRI`),
  then `nIdx` teams × `nRows` u32 result cells. Lookup loop matches a team id (`unaff_EBX`) against
  the index table with paging every 16 entries (re-reads via `FUN_004cfaa0` when `(uVar4 & 0xf)==0`
  ⇒ records stream in 16-entry pages).
- `.TRI` = string pool for the same ids: DU.TRI starts u32 count=**43**, then a u16 offset table,
  then pooled NUL-terminated strings (record iterator `FUN_0049f5a0/49f750` walks 4-byte length +
  bytes per string; the bracket loader copies fields into fixed slots of **0x300 stride** records at
  `DAT_00631b18 / c1c18 / c1d18 / c1e18 ...` = 6 strings per team record, truncation caps 255/127 B).

## Confirmed — tournament participant loader (`FUN_0048c0bc`, size 2328)
- Reads `fe\teamhist.<lang>\du.tri` (string ref @0x564... via 0x48c142), iterates records, and fills
  team metadata: name, short, group label etc. into the six string slots above; per-record index comes
  from a 3×u32 pot structure (`local_9c[10]`, stride 0xc) built by the same pass.
- Modes at `DAT_0057e92c`: **0 = shuffle** (Fisher–Yates via RNG `FUN_004c321c` over the pot order —
  random draw), **1/2 = deterministic cycling** (`DAT_0057e930/e934` modular counters index teams,
  i.e. saved/real fixture ordering); mode 9 remaps three ids through a hardcoded table at 0x48bf6e
  (43-entry u16 pair map).
- Art assets for the bracket screen: `fe\pack\brdxf.pak`, `fe\brdxf.mdl`, `fe\brdxf.fsh`
  (strings @0x5664e8..; model+textures = rendered bracket, layout from `.LAY`).

## Hypothesis — tournament structure encoding
1998 format (32 teams → group stage → knockout) is encoded by: HIS/TRI pair contents (results +
names), the pot/seed table in `FUN_0048c0bc`, FE flow screens FEFLOW* selecting fixtures, and FCDB
team ids. No standalone "schedule" file found on disk (inventory §2 census has no candidate) ⇒
fixture generation is code+data-table driven inside those loaders; exact bracket slot assignment =
open item.

## Disk survey (2026-11-03, all 9 language dirs)
- Every `FE/TEAMHIST.<lang>/*.HIS` shares the identical binary header: u32 @0 = **0x30028**
  (= magic '0x30' + declared index span 40), `u16@0x1e nRows=49`, `u16@0x20 nIdx=52`; the geometry
  predicate passes (10,304 ≤ every file size). Files differ only in total size
  (161.7 KB SW .. 173.6 KB FR) = **language string lengths** ⇒ per-language record payloads embed
  localized strings inline; the numeric result matrix is language-invariant.
- Index table u16 values at +0x28: {26,29,31,…} sequential-with-gaps ids — the 43-team participant
  set (same count as DU.TRI) embedded in a 52-row container ⇒ rows 43.. = BYE/qualifier slots.
- Open: per-cell semantics of the 52×49 matrix + inter-page record framing (stream API paging).
  Full semantic decode is assigned to the tournament implementation slice; the participant list for
  team-selection UI needs only TRI strings + index ids, which are fully specified above.
