# TMMNG_FORMAT_NOTES — Team Management tactics DB on WC98

## Status: file absent from the CD; engine support present (loader lane decoded)

> Retraction (2026-11-18): a commit message in pass-44forensic claimed an
> "installer boot" decode (3000–7929 byte window, per-player 27-bit bitstream,
> `FUN_004d0770` stream reader, 593×417 pitch, 459/459 install records). No
> artifact supports it anywhere in this repo or the parent analysis tree — the
> claim is withdrawn. The verified state is exactly what this document records
> below.

`WorldCup98_Extracted/USER/` contains only `options.sav` — no `tmmng.db`, `custom.db`,
`cusplyr.db`, `xfer.db`. The engine nevertheless loads all four files if a user creates
them. Loader lane verified byte-by-byte (disassembly, this pass):

**PE mapping (from section headers):** code section `AUTO`: VA = raw + `0x400C00`;
data section `DGROUP`: VA = raw + `0x401A00`; `.bss` is not in the file (VA base
`0x598000`, image base `0x400000`). Earlier versions of this document used the
`raw + 0x400000` mapping and quoted wrong VAs (`0x564524`…) and wrong "registration
sites" (`0x46df95` + `call 0x4a50a0`): those came from an off-by-`0x1A00`/`0x400000`
scan and are **replaced** by the sites below.

* Filename strings (DGROUP raw `0x164521..0x164544`): `xfer.db` VA `0x565f24`,
  `tmmng.db` VA `0x565f2c`, `custom.db` VA `0x565f38`, `cusplyr.db` VA `0x565f44`;
  format template `user\%s` VA `0x565fa8`; `common\fcdb_%s.dbi` VA `0x565f6c`.
* Filename **pointer table** VA `0x57d89c..0x57d8a8` (raw `0x17be9c`, initialized data):
  4 dwords = the four string pointers above.
* **Selector table** VA `0x57d88c..0x57d898` (initialized): dwords `{1, 2, 4, 8}` —
  bit selectors per file (xfer/tmmng/custom/cusplyr).
* Loader fn `0x47b08c` (called from `0x45946e`): iterates the 4 selector slots; for each
  selected file it `sprintf("user\\%s", name)` (format fn `0x49168e`), opens it
  (`0x439870`). If the open **succeeds** → `fn 0x47af18(fd, selector)` reads it (below),
  then `fclose` (`0x42b070`). If the file is **missing** → `selector-1` indexes jump table
  `0x47b06c` and registry bookkeeping runs (`FUN_004d2bf0/004d3170/004d31a0`).
  **Pass-46 correction:** those three functions are linked-list maintenance helpers
  (`+0x1c` next pointer, payload dwords `+0x10`/`+0x14`; decompile in
  `analysis/pass46tmmng/defdecomp.txt`), and `0x588224/0x588250/0x58827c/0x5882a8`
  (stride `0x2c`) are the **registry slot pool** itself — `FUN_004d2480(type, slot)`
  allocates entries at `DAT_005881a4 + slot*0x2c` and `.bss` is zero-filled. A missing
  file therefore installs an **empty slot**, not embedded default bytes: there is no
  byte-exact default-tactics table in the image, and retail tactics/positioning come
  from the FCDB team record + `GEN4TBLS.VIV` G98*.FMT lane
  (`TEAM_AND_FORMATION_REFERENCE.md`) as integrated.
* Container reader `fn 0x47af18(fd, selector)`: header = `FCDB` magic (string VA
  `0x565f94`) + version dword@4 == `0x10000`; data pointer = header dword@`0xC`
  (= start byte); section pointers accumulate from `hdr[0xC]` with sizes at
  `hdr[0x10]`, `hdr[0x14]`, `hdr[0x18]`. Each selected section is installed as a typed
  registry entry `FUN_004d2480(type, ptr)`: bit0 xfer → type **5**, bit1 tmmng →
  type **6**, bit2 custom → type **3**, bit3 cusplyr → type **4**. Registry internals
  beyond `0x4d2480` not traced.
* `xfer.db` lane also reached from fn `0x47b000` (selector slot 0); `common\fcdb_%s.dbi`
  loader at `0x47ac14` (template copy `0x47aae0`, fopen `0x439810`).

Conclusion: `USER\tmmng.db` is created/updated at runtime when Team Management saves.
It is generated by the user, never shipped; retail defaults come from the built-in
record blocks above plus the FCDB team record + formation module
(`TEAM_AND_FORMATION_REFERENCE.md`).

## Editor grammar (fifa98edit `read_tmmng`/`write_tmmng`, `__init__.py:4331/4434`, RTWC98 — reference only)

`write_tmmng` header (big-endian-ish byte writes):

| Header byte(s) | Value |
|---|---|
| 0..3 | `FCDB` |
| 4..7 | `\x00\x00\x01\x00` — version, LE dword `0x10000` (**matches engine check**) |
| 2..3 | file length u16 LE (patched last: `tempFile[2]`) |
| 6..7 | body length u16 LE (`len - startByte`, patched: `tempFile[6]`) |
| 12 | `startByte = 32` — data start (**matches engine dword@0xC**) |
| 32..33 | `n_teams` u16 LE (writes 3 bytes + `0x06` marker byte@35) |

Per-team record (what `read_tmmng` consumes: **76 B**): id = 2 B (`byte[1]&3` + high →
10-bit team id, overlaps tactics word); tactics 2 B:
`mid=(b0&192)>>6, def_l1=(b0&56)>>3, def_l2=(b0&12)>>2, mid_bit=b1&1,
strikers=(b1&14)>>1, att_line=(b1&128)>>7, mid_line=(b1&64)>>6, def_line=(b1&32)>>5`;
formation = `[def_l1+def_line, mid+4*mid_bit, strikers]` with per-line `d` (diamond)
flags; then 5 × [3 B packed positions + 1 B attack-bias nibble pair]; 2 B
`strategy` + position of 11th player; 5 B pad + 1 B GK attack + 3 B pad + 1 B GK
aggression; lineup = 11 player ids, 4 B per pair packed (`id &64512 >>2`, `id&768 <<14`,
`id&60 >>2`, `id&3 <<14`, pair aggression nibble); set-piece = 9 taker ids same packing
(pair aggression nibbles from `aggression[5..9]`); aggression bytes re-read from
`init_players+4` (9 × seek-3 read-1, hi nibble).

Position codec (`_conv_position`/`_read_position`): `pos = (lon&3)<<8 | lat<<4 |
(lon&12)>>2`; decode `lat=(pos&240)>>4`, `lon=((pos>>8)&3)+((pos&3)<<2)` — a 12-bit
pitch coordinate, not a pitch-metre float. Set pieces: editor exposes 9 slots
(`range(1,10)`); the goal's corner/free-kick/penalty/knockout lists map onto these at
most — WC98 semantics unverified.

Quirk: editor verbose prints size at `seek(8)`, but the writer patches length into
bytes **2..3**; its own `seek(8)` read is inconsistent with its writer (RTWC artifact —
do not copy).

## What is verifiable on WC98

1. The runtime system the saved file feeds is the ported formation module:
   `Team_initPlayers 0x451210` tactics block (team +0x0C..+0x183), three formation records
   `+0x16 + i*0x6E` {mentality, slot entries u8 used, i8 dx, i8 dz, u16 tag}
   (`simulation/src/squad.cpp slotRec`), set-piece taker preference tables 0x586AEC/0x586B30
   consumed by `takerByOrder 0x4A0F3C`, base-slot lookup `0x4A0888`.
2. Byte-exactness of the saved layout is **unverified** for WC98: the file cannot be
   generated from the CD alone, and the original Windows release cannot reach Team
   Management under Wine (DirectDraw capture proven dead, `WINE_ORACLE_WC98.md`).
   Do not assume the RTWC 76 B record layout equals the WC98 layout — the header framing
   (FCDB magic, version `0x10000`, start byte@12) is shared, the record contents are not.
3. Nothing in the repo reads or writes `tmmng.db`. Re-verification path (if a user ever
   generates the file on original Windows): parse with the engine grammar above, then
   compare slot entries against the `slotRec` record layout and the `kSlotFill` role
   masks (exe `0x586B74`).

## Consequence for acceptance criteria

Original formations/positioning on WC98 come from the FCDB (tactics byte, role byte,
`GEN4TBLS.VIV` G98*.FMT coordinate tables) — recovered and integrated. The user-editable
tactics file exists as an engine concept (loader lane decoded; default-block mapping
partial, registry internals untraced) with no shipped content
to recover; recorded as a documented gap, not a fabricated assumption.
