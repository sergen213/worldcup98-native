# Gameplay Discrepancy Register — second-pass forensic audit (2026-11-10/11)

Pass-2 objective: treat every existing implementation as **unverified until independently tested**,
and enumerate the concrete differences between the port and the original Windows release
(`WorldCup98_Extracted/FIFAWC.EXE`, Watcom PE32 built 1998-04-13). This register is the working
list; `GAMEPLAY_PARITY.md` keeps the per-system status registry, this file keeps the
**discrepancy-level evidence and correction state**.

Legend for Status: **Open** = confirmed discrepancy, not corrected. **Fix-batch-N** = scheduled.
**Fixed** = corrected + gated (gate name cited). **Blocked** = RE route exhausted; technical
explanation in the row. **Non-defect** = documented faithful-state/data-absence, no correction due.

Severity: **Critical** = fundamentally incorrect gameplay / missing original behavior.
**High** = noticeably different physics/controls/animation/AI/match interaction.
**Medium** = timing/responsiveness/positioning/behavioral difference.
**Low** = minor, limited gameplay impact.

Evidence anchors used below: `HANDLER_DIFF_AUDIT.md` (pass-11 per-handler verdict table + P-list),
`SIM_PORT_NOTES.md` "OPEN items", `GHIDRA_PASS5_IG.md` (exe tick-chain field tables),
`GAMEPLAY_PARITY.md` §4/§5, `docs/STATUS.md` Known limitations. Reproduction convention: original
side = Ghidra decompile at the cited VA (`ghidra/wc98` project, PyGhidra lane); port side = named
ctest gate or `wc98-native --self-test FILE.json` step; Wine live capture is **blocked** for
in-match state (wined3d 24 bpp AV path — `WINE_ORACLE_WC98.md`), so no row claims a live-original
capture it does not have.
